# Задача 3

- 100 виртуальных машин на базе Linux и Windows, общие задачи, нет особых требований. Преимущественно Windows based-инфраструктура, требуется реализация программных балансировщиков нагрузки, репликации данных и автоматизированного механизма создания резервных копий.
	Microsoft Hyper-V. Идеальный выбор для Windows инфраструктуры, встроен в Windows Server, идеально интегрируется с AD, PowerShell, VSS. Есть все необходимые механизмы: репликация (Hyper-V Replica), Live Migration, Failover Clustering, резервное копирование.

- Требуется наиболее производительное бесплатное open source-решение для виртуализации небольшой (20-30 серверов) инфраструктуры на базе Linux и Windows виртуальных машин.
	Proxmox. Бесплатный, поддерживает и Linux и Windows в качестве гостевой ОС, простое управление через веб-интерфейс, производительность близка к нативной.

- Необходимо бесплатное, максимально совместимое и производительное решение для виртуализации Windows-инфраструктуры.
	VMware ESXi. Стабильный, бесплатный, производительный, поддерживает Windows как гостевую ОС.

- Необходимо рабочее окружение для тестирования программного продукта на нескольких дистрибутивах Linux.
	VirtualBox. Бесплатный, очень простой, для тестирования подойдет отлично.


# Задача 4

- Опишите возможные проблемы и недостатки гетерогенной среды виртуализации (использования нескольких систем управления виртуализацией одновременно) и что необходимо сделать для минимизации этих рисков и проблем. Если бы у вас был выбор, создавали бы вы гетерогенную среду или нет?
	Основными недостатками гетерогенной среды являются: сложность управления и администрирования, несовместимость форматов, сложность миграции, сложность обеспечения высокого уровня безопасности, сложность мониторинга, отсутствие единой точки управления.
	Для минимизации рисков необходимо стандартизировать процессы, использовать общие инструменты мониторинга и бэкапа, а также автоматизацию.
	На мой взгляд можно строить гетерогенную среду, но с разумным подходом. Например иметь контейнеризацию в виде кластера Kubernetes для удобного и быстрого развертывания приложений и сервисов, а так же виртуальные машины, например на Proxmox для кластеров баз данных, мониторинга, сервера РК и т.д. Такая схема не сильно усложнит администрирование, при этом ВМ дадут стабильность и производительность для постоянных сервисов, а контейнеризация даст удобную интеграцию с системами контроля версий, быстрое развертывание и масштабируемость для приложений.
